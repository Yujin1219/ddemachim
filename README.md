# Ddemachim Agent Guide

이 프로젝트는 프론트엔드, 백엔드, 데이터 작업을 분리하고 각 영역의 전문 에이전트가 순차적으로 협업하도록 구성되어 있다.

에이전트 설정은 `.codex/agents/*.toml`, 전체 작업 분배 규칙은 `AGENTS.md`, Codex 멀티 에이전트 설정은 `.codex/config.toml`에 있다.

## 전체 구조

총 15개 역할로 구성된다.

- 상위 코디네이터 3개: 작업 범위 판단, 전문 에이전트 호출, 결과 취합
- 하위 전문 에이전트 12개: 맥락 파악, 오류 분석, 코드 작성, 문서화

각 코디네이터는 다음 순서를 지킨다.

```text
맥락 파악
-> 기존 오류 및 위험 분석
-> 코드 작성
-> 작성 결과 재검증
-> 필요한 문서 갱신
```

쓰기 가능한 에이전트는 동시에 실행하지 않는다. 여러 영역의 데이터 계약이 함께 변경되는 작업은 `데이터 -> 백엔드 -> 프론트엔드` 순서로 진행한다.

## 프론트엔드 에이전트

담당 범위는 `FE/**`이다.

### `frontend_coordinator`

프론트엔드 작업의 상위 관리자다. 요청과 앞 단계의 결과를 각 전문 에이전트에 전달하고, 모든 작업이 끝나면 변경 파일, 검증 결과, 남은 위험을 하나의 보고서로 정리한다. 직접 코드를 작성하는 것은 하위 에이전트가 진행할 수 없는 작은 통합 수정으로 제한한다.

### `frontend_context`

읽기 전용 맥락 조사 담당이다. 라우트, 컴포넌트, 상태 관리, 스타일, 에셋, API 계약, 패키지 스크립트와 테스트를 조사한다. 관련 파일과 심볼, 현재 동작, 기존 구현 패턴, 제약 조건과 적절한 검증 명령을 정리한다.

### `frontend_error`

읽기 전용 오류 분석 및 재검증 담당이다. 빌드와 런타임 오류, 상태 처리, 내비게이션, 반응형 UI, 접근성, 애니메이션과 API 계약 문제를 확인한다. 코드 작성 전에는 위험 요소를 찾고, 작성 후에는 실제 변경 내용을 다시 검사한다.

### `frontend_writer`

실제 프론트엔드 코드를 작성한다. 기존 React, 라우팅, 상태 관리, 스타일과 모션 패턴을 유지하며 필요한 범위만 수정한다. 관련 테스트, 린트, 타입 검사 또는 빌드를 실행한다.

### `frontend_documenter`

프론트엔드 동작, 설정, API 사용법 또는 개발 절차가 달라진 경우 관련 문서와 예제를 갱신한다. 애플리케이션 로직은 수정하지 않으며 문서 변경이 필요하지 않으면 작업하지 않는다.

## 백엔드 에이전트

담당 범위는 `BE/**`이며, `BE/AGENTS.md`와 `BE/CLAUDE.md`의 백엔드 규칙을 따른다.

### `backend_coordinator`

백엔드 작업의 상위 관리자다. 백엔드 전문 에이전트를 정해진 순서로 호출하고 API 및 데이터 계약 영향, 변경 파일, 테스트 결과와 남은 위험을 취합한다.

### `backend_context`

읽기 전용 맥락 조사 담당이다. Controller, Service, Repository, Entity, DTO, 보안 설정, 마이그레이션, 테스트와 빌드 구성을 파악한다. 현재 API 및 데이터 계약과 기존 아키텍처 규칙을 정리한다.

### `backend_error`

읽기 전용 오류 분석 및 재검증 담당이다. 컴파일과 런타임 문제, 입력 검증, 인증과 인가, 트랜잭션 경계, JPA 동작, N+1 쿼리, 동시성, 오류 응답 계약, 마이그레이션과 테스트를 검사한다.

### `backend_writer`

Spring Boot 코드와 테스트를 작성한다. 기존 아키텍처와 API 계약, 트랜잭션 규칙을 유지하고 위험 범위에 맞는 테스트를 추가한다. 구현 후 관련 Gradle 검사를 실행한다.

### `backend_documenter`

API/OpenAPI 문서, 마이그레이션 안내, 설정 방법, 운영 절차와 예제를 관리한다. 계약이나 사용법이 변경된 경우에만 문서를 수정하며 애플리케이션 로직은 변경하지 않는다.

## 데이터 에이전트

담당 범위는 `data-pipeline/**`, 데이터베이스 스키마, 마이그레이션, 수집, 정규화, 적재 및 공통 데이터 계약이다.

### `data_coordinator`

데이터 작업의 상위 관리자다. 파이프라인과 스키마 관련 전문 에이전트를 순차적으로 호출하고, 스키마 및 계약 영향, 변경 파일, 검증 결과와 남은 위험을 취합한다.

### `data_context`

읽기 전용 맥락 조사 담당이다. 수집기, 정규화 처리, 로더, 스키마, 마이그레이션, 품질 검사와 테스트를 분석한다. 공통 계약을 이해하는 데 필요한 경우에만 백엔드 Entity나 프론트엔드 소비 코드를 참고한다.

### `data_error`

읽기 전용 오류 분석 및 재검증 담당이다. 멱등성, 중복 제거, 정규화, 스키마 불일치, NULL 처리, 데이터 품질, 재시도 동작, 트랜잭션 안전성, 마이그레이션 호환성과 테스트를 검사한다.

### `data_writer`

데이터 파이프라인과 명시적으로 필요한 스키마 및 마이그레이션 코드를 작성한다. 처리를 반복 실행할 수 있고 관찰 가능하며 멱등하게 설계한다. 외부 시스템에 데이터를 쓰는 작업은 사용자의 명시적인 허가 없이는 실행하지 않는다.

### `data_documenter`

데이터 계보, 데이터 사전, 스키마 설명, 파이프라인 실행법, 마이그레이션 안내와 운영 문서를 관리한다. 처리 로직은 수정하지 않는다.

## 공통 안전 규칙

- 하위 전문 에이전트는 다른 에이전트를 생성하지 않는다.
- 최상위 에이전트만 영역별 코디네이터를 호출한다.
- 사용자가 이미 작업한 관련 없는 변경은 되돌리지 않는다.
- `.env`, 자격 증명, 비밀 값, 데이터베이스 덤프와 비공개 데이터는 읽거나 노출하지 않는다.
- 읽기 전용 요청에서는 코드 작성 및 문서화 에이전트가 파일을 수정하지 않는다.
- 구현 후 관련 테스트나 빌드를 실행하고 검증하지 못한 항목을 명시한다.

## 사용 예시

Codex에서 별도의 에이전트 이름을 직접 지정할 필요 없이 원하는 작업을 자연어로 요청하면 된다.

```text
탐색 화면의 장소 목록 로딩 오류를 찾아서 수정해줘.
```

프론트엔드 코디네이터가 맥락 조사, 오류 분석, 구현, 재검증과 문서화 필요 여부 확인을 순차적으로 진행한다.

```text
즐겨찾기 기능을 DB부터 API와 프론트 화면까지 구현해줘.
```

공통 계약이 변경되므로 데이터, 백엔드, 프론트엔드 코디네이터가 순차적으로 작업한다.

```text
백엔드 인증 코드에서 보안 문제만 검토하고 수정은 하지 마.
```

백엔드 에이전트들이 읽기 전용으로 조사하고 코드 작성 및 문서화 단계는 변경 없이 종료한다.

## 설정 파일

```text
AGENTS.md                    최상위 작업 분배 및 공통 규칙
.codex/config.toml           멀티 에이전트 실행 설정
.codex/agents/*.toml         15개 에이전트 역할별 설정
BE/AGENTS.md                 백엔드 전용 개발 규칙
BE/CLAUDE.md                 Claude용 백엔드 지침 진입점
```

에이전트 설정을 변경한 뒤에는 새 Codex 작업을 열거나 Codex를 다시 시작해야 변경된 역할이 확실하게 반영된다.
