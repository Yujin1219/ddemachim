## 1. 서비스 개요

### 한 문장 정의

> **최근 주목받는 서울의 장소를 발견하고, 사용자가 자유롭게 담은 장소와 개인 필수 일정을 방문하기 좋은 시간의 하루 코스로 연결하며, 여행 중에는 현재 위치에 맞는 현장 정보와 일정 변경안을 제공하는 서비스**
> 

### 핵심 가치

본 서비스는 단순히 인기 장소를 추천하거나 장소를 가까운 순서로 연결하지 않는다.

팝업 종료 시간, 메뉴 품절 가능성, 꽃 개화 상태, 촬영하기 좋은 시간, 운영시간, 혼잡도처럼 **장소의 방문 가치가 달라지는 조건**을 고려해 실제로 실행할 수 있는 하루 일정을 만든다.

> **장소를 추천하는 서비스가 아니라, 지금 그 장소에 가야 하는 이유와 가장 적절한 방문 순서를 제공한다.**
>

## 2. 해결하려는 문제

사용자는 SNS, 블로그, 영상 콘텐츠를 통해 가고 싶은 장소를 발견하지만, 실제 여행을 계획하려면 여러 서비스를 오가며 정보를 다시 확인해야 한다.

- 최근 어떤 장소가 주목받는지 확인
- 장소가 유명해진 구체적인 이유 확인
- 정확한 위치와 운영시간 검색
- 팝업과 전시의 운영 기간 확인
- 여러 장소를 지도에 저장
- 장소 사이 이동시간 계산
- 방문 순서 결정
- 다이소, 약속 장소, 예약 식당 등 개인 일정 추가
- 여행 중 혼잡도와 마감시간 재확인
- 방문 후 사진과 후기를 별도로 정리

특히 다음과 같은 정보는 일반 지도 서비스의 기본 정보만으로 확인하기 어렵다.

- 평범한 카페의 특정 디저트가 최근 유명해진 경우
- 기존 담장이나 골목에 꽃이 피어 사진 명소가 된 경우
- 드라마 방영 이후 특정 촬영지가 다시 주목받는 경우
- 특정 위치와 구도로 찍는 사진이 유행하는 경우
- 며칠 뒤 종료되는 팝업이나 전시
- 오후에 자주 품절되는 메뉴
- 특정 시간대에 빛이나 풍경이 좋은 장소

본 서비스는 다음 과정을 하나로 연결한다.

```
장소 발견
→ 장소 상세 확인
→ 코스 바구니에 추가
→ 개인 필수 일정 추가
→ 주변 장소 추천
→ 방문 순서 생성
→ 여행 중 현장 안내
→ 후기 및 코스 공유
```

## 3. 주요 타깃

### 주 타깃

SNS나 블로그에서 서울의 장소를 저장하지만, 여러 장소를 실제 하루 일정으로 구성하는 데 어려움을 느끼는 20~30대 이용자

- 최신 팝업과 화제 장소에 관심이 있음
- 카페, 전시, 촬영지, 포토존을 섞어 방문함
- 도보와 대중교통을 중심으로 이동함
- 이동 효율뿐 아니라 사진, 혼잡도, 분위기를 중요하게 생각함
- 관광 장소 사이에 개인 용무가 포함될 수 있음

### 부 타깃

영화, 드라마, 예능, 아티스트와 관련된 장소를 방문하는 팬 이용자

- 작품별 촬영지 탐색
- 원작 장면과 같은 구도로 사진 촬영
- 촬영지와 주변 장소를 함께 코스로 구성
- 방문한 촬영지와 사진 기록

## 4. 서비스 핵심 원칙

### 4.1 테마는 코스 종류가 아니라 장소를 발견하는 입구

사용자가 처음부터 하나의 테마만 선택하게 하지 않는다.

홈에서 여러 테마의 장소를 탐색하고 자유롭게 섞어 담도록 한다.

예:

- 이번 주 팝업
- 드라마 촬영지
- 능소화 사진 명소
- 최근 디저트가 유명해진 카페
- 반드시 방문해야 하는 다이소

```
여러 테마에서 장소 발견
→ 가고 싶은 장소를 자유롭게 조합
→ 선택한 장소를 기반으로 코스 생성
```

---

### 4.2 모든 장소를 직접 수집하지 않는다

장소는 두 종류로 구분한다.

#### 서비스 큐레이션 장소

‘지금 방문할 이유’를 함께 제공하는 장소

- 촬영지
- 팝업
- 전시·행사
- 계절 명소
- 포토스팟
- 최근 특정 메뉴가 주목받는 카페
- 현장에서 볼 이야기가 있는 문화시설

#### 일반 장소

사용자가 검색해 개인 일정으로 추가하는 장소

- 음식점
- 카페
- 다이소
- 약국
- 숙소
- 은행
- 예약 장소
- 친구와의 약속 장소

일반 장소는 상세 큐레이션 콘텐츠가 없어도 코스 계산에 포함할 수 있다.

---

### 4.3 자동 추천보다 사용자의 선택을 우선한다

장소는 다음과 같이 구분한다.

| 구분 | 의미 | 처리 방식 |
| --- | --- | --- |
| 꼭 갈 곳 | 반드시 방문해야 하는 장소 | 코스에서 자동 제거하지 않음 |
| 가고 싶은 곳 | 가능하면 방문하고 싶은 장소 | 시간 안에서 최대한 포함 |
| 추천받을 곳 | 서비스가 제안하는 장소 | 사용자 승인 후 포함 |

추천 장소를 서비스가 임의로 코스에 삽입하지 않는다.

---

### 4.4 자유 후기는 사람에게, 선택형 평가는 알고리즘에 활용한다

자유 후기 문장을 분석해 코스에 직접 반영하지 않는다.

예:

> 생각보다 별로였어요. 사진은 예쁜데 사람이 너무 많았어요.
> 

이러한 문장은 맥락과 주관성이 크기 때문에 다른 이용자의 참고용으로만 제공한다.

코스 계산에는 사용자가 명시적으로 선택한 값만 활용한다.

- 추천 / 중립 / 비추천
- 추천·비추천 이유
- 혼잡 정도
- 대기시간
- 실제 체류시간
- 품절 여부
- 개화 상태
- 추천 시간대

```
자유 후기·사진
→ 다른 이용자의 참고 정보

선택형 평가
→ 추천 후보 정렬

대기·혼잡·체류시간
→ 예상 일정 보정
```

## 5. 전체 사용자 흐름

### 1단계. 장소 발견

홈에서 여러 테마별 장소를 카드 형태로 확인한다.

### 2단계. 장소 상세 확인

장소 기본 정보, 지금 가야 하는 이유, 최신 현장 정보와 사용자 후기를 확인한다.

### 3단계. 코스 바구니에 추가

장소를 `꼭 갈 곳` 또는 `가고 싶은 곳`으로 추가한다.

### 4단계. 개인 일정 추가

다이소, 약속 장소, 예약 식당처럼 서비스가 큐레이션하지 않은 장소를 검색해 추가한다.

### 5단계. 주변 추천 확인

선택한 장소 사이에서 방문 가능한 추가 장소를 추천받는다.

### 6단계. 여행 조건 입력

- 출발지
- 출발 시각
- 종료 희망 시각
- 코스 밀도
- 이동 성향
- 고정 예약시간
- 장소별 체류시간

### 7단계. 코스 생성 및 비교

빠른 코스와 편한 코스 등 복수의 후보를 비교한다.

### 8단계. 여행 진행

현재 위치, 다음 장소, 예상 도착시간과 현장 콘텐츠를 확인한다.

### 9단계. 후기 작성 및 코스 공유

장소별 후기와 실제로 방문한 코스를 기록하고 공개할 수 있다.

### 8.2 네이버 블로그 검색 기반 화제 장소 발견

블로그 검색 결과는 위치를 직접 제공하는 장소 데이터가 아니다.

검색 API에서는 일반적으로 제목, 요약, 링크, 작성일 등을 받고, 블로그 본문에 지도 카드가 첨부돼 있어도 그 장소 좌표가 검색 결과에 바로 포함되지는 않는다.

따라서 다음 흐름으로 처리한다.

```
블로그 검색 결과 수집
→ 제목·요약에서 메뉴명·장소명·지역명 후보 추출
→ 장소명과 지역명으로 로컬 API 검색
→ 주소·좌표·장소 후보 확보
→ 동일 장소 여부 검증
→ 해당 장소에 화제 요소 연결

팝업 같은 경우는 장소가 kakao 맵 api 에 있지 않음 -> 
. 각 글의 link로 실제 포스트 페이지 요청 (PostView.naver)
3. HTML에서 se_module_data(v2_map) JSON 파싱 → 장소명+주소+좌표+전화번호 확정
4. 장소 없는 글은 건너뜀 (지도 첨부 안 한 글)
5. 좌표 있는 것만 바로 지도에 표시 — 카카오 검증 단계 자체가 필요 없어짐
좌표 없는 거만 kakao api 호출
```

### 파이프라인

1. 네이버 블로그 검색 API
→ 검색어(지역+카페/팝업)로 블로그 글 목록 수집 (제목, 요약, 링크, 날짜)
2. 텍스트에서 후보 추출 (규칙 기반)
→ 글에서 장소명, 지역명, 화제 키워드(메뉴 등) 후보 추출
3. 위치 정보는 두 갈래로 확보
a) 카카오 로컬 API → 카페/베이커리처럼 상설 매장은 여기서 좌표 확보
(텍스트 추출 없이 카카오에서 직접 장소를 검색하는 방식도 병행)
b) 블로그 본문에 첨부된 지도 데이터 파싱 → 팝업처럼 카카오에 없는
임시 매장은 블로거가 직접 찍은 좌표를 블로그 본문 HTML에서 추출
4. 카카오맵 JS SDK로 지도 시각화

예:

```
검색 결과:
“안국 OO카페 딸기 수건 케이크 후기”

추출:
장소명 후보: OO카페
지역 후보: 안국
화제 요소: 딸기 수건 케이크

장소 검색:
“OO카페 안국”

결과:
장소 ID·주소·위치 확보
```

장소명이 없거나 같은 이름의 지점이 여러 개라면 자동 확정하지 않고 관리자 검수 대상으로 보낸다.

---

### 8.3 관리자 검수

자동으로 발견한 정보는 바로 사용자에게 공개하지 않는다.

관리자는 다음을 확인한다.

- 실제 장소명
- 정확한 지점과 좌표
- 화제 요소의 존재
- 운영기간
- 공식 출처
- 최신성
- 광고성 게시물 여부
- 사유지·주거지역 여부
- 정보 유효기간

관리자 후보 카드 예시:

```
검색어: 안국 수건 케이크
추출 장소: OO카페
최근 관련 글: 12건

장소 후보
○ OO카페 안국점
○ OO카페 대학로점

[장소 연결] [보류] [제외]
```

## 9. 화제 요소 관리

장소와 그 장소에서 최근 주목받는 요소를 분리해 관리한다.

| 유형 | 예시 |
| --- | --- |
| MENU | 특정 디저트·음료 |
| PRODUCT | 한정 굿즈·상품 |
| POPUP | 기간 한정 팝업 |
| FLOWER | 벚꽃·능소화·단풍 |
| PHOTO_SPOT | 최근 많이 찍는 위치 |
| SCENE | 영화·드라마 촬영 장면 |
| SEASONAL_VIEW | 일몰·야경·계절 풍경 |
| SPACE_DETAIL | 계단·창가·벽면 |
| EVENT | 전시·축제·행사 |

화제 정보에는 반드시 다음을 포함한다.

- 확인일
- 유효 시작일
- 유효 종료일
- 정보 출처
- 검수 상태
- 신뢰 수준

팝업, 꽃, 품절 정보처럼 유효기간이 지난 콘텐츠는 자동으로 노출을 중단한다.

## 11. 주변 장소 추천

선택한 장소, 남는 시간과 사용자 취향을 기준으로 주변 장소를 제안한다.

### 추천 기준

- 다음 일정까지 남은 시간
- 운영시간
- 사용자 선호 태그
- 최근 추천 평가
- 기간 한정 여부
- 예상 혼잡도
- 전체 예산
- 추천 장소를 추가한 뒤의 일정 지연 여부

예:

> 
>

>

>


## 12. 코스 생성

### 12.1 입력 조건

- 출발 위치
- 출발 시각
- 종료 희망 시각
- 꼭 갈 곳
- 가고 싶은 곳
- 고정 예약시간
- 장소별 체류시간
- 코스 밀도
- 이동 성향
- 예산

### 12.2 생성 순서

```
1. 고정 시간이 있는 장소 배치
2. 꼭 갈 곳 배치
3. 운영시간과 마감시간 확인
4. 가고 싶은 곳을 가능한 범위에서 삽입
5. 복수의 초기 코스 생성
6. 장소 순서를 반복 교환해 이동시간 개선
7. 실제 경로와 이동시간 확인
8. 코스별 조건 점수 계산
9. 복수 코스 제시
```

### 12.3 코스 계산 요소

```
이동시간
+ 체류시간
+ 운영시간 위반
+ 예약시간 위반
+ 예상 대기시간
+ 혼잡도
+ 보행 피로도
+ 방문 적정 시간 위반
+ 기간 종료 임박도
- 사용자 평가 보조점수
```

사용자 추천 평가는 코스 전체를 결정하는 핵심값이 아니라, 조건이 비슷한 후보 장소 사이의 순위를 조정하는 보조값으로 사용한다.

## 14. 여행 진행 모드

데모는 모바일 웹앱으로 구현한다.

사용자가 `코스 시작`을 누르고 진행 화면을 열어둔 동안 브라우저 위치정보를 이용한다.

### 제공 기능

- 현재 위치 표시
- 다음 목적지
- 예상 도착시간
- 남은 일정
- 위치 변화에 따른 목적지 접근 판정
- 촬영지 장면 카드
- 주변 화제 장소 안내
- 마감 임박 안내
- 혼잡 변화 안내
- 남은 코스 재계산

### 웹앱 데모 제약

다음 기능은 보장하지 않는다.

- 브라우저가 종료된 상태의 위치 추적
- 화면이 꺼진 상태의 지속적인 감지
- 네이티브 앱 수준의 백그라운드 지오펜싱

따라서 데모 기능은 다음처럼 정의한다.

> **사용자가 코스 진행 화면을 실행한 동안 위치를 확인하고, 장소의 도달 범위에 들어오면 화면 내 알림과 현장 콘텐츠를 제공한다.**
>

```
너무 붐벼요

사진 찍기 어려워요
```

## 17. 후기 데이터 활용

### 추천 평가

최소 평가 수를 충족한 뒤 서비스 추천 후보 정렬에 약하게 반영한다.

- 평가 수 부족: 코스 점수 미반영
- 평가 수 충족: 추천 후보 간 보조 순위로 반영

사용자가 선택한 `꼭 갈 곳`은 비추천 평가가 많아도 제거하지 않는다.

대신 경고와 대체 장소를 제시한다.

### 시간에 민감한 정보

| 정보 | 활용 기간 예시 |
| --- | --- |
| 현재 혼잡도 | 2~3시간 |
| 대기시간 | 당일 또는 유사 시간대 |
| 메뉴 품절 | 당일 |
| 팝업 굿즈 품절 | 당일 |
| 꽃 개화 | 2~3일 |
| 추천·비추천 | 최근 수개월 |
| 촬영 구도 | 장기 |

## 18. 코스 기록 및 공유

여행이 끝나면 실제 방문 결과를 바탕으로 코스 기록을 만든다.

- 실제 방문 순서
- 총 소요시간
- 이동거리
- 방문 장소 수
- 계획 대비 완료율
- 장소별 사진
- 장소별 후기
- 건너뛴 장소

공개 범위:

- 전체 공개
- 링크 공유
- 비공개

다른 사용자는 공개된 코스에서 다음 기능을 사용할 수 있다.

```
[이 코스 담기]
[일부 장소만 담기]
[내 조건에 맞게 다시 만들기]
[저장]
```

`내 조건에 맞게 다시 만들기`는 원본 코스를 그대로 복사하지 않고, 사용자의 출발시간, 필수 장소와 이동 성향에 맞춰 다시 계산한다.

## 23. 추후 발전 방향

### 대화형 여행 챗봇

사용자가 자연어로 조건을 입력하면 장소와 일정 조건으로 변환한다.

> 오후 1시부터 7시까지 안국에서 놀고 싶어.
> 
> 
> 팝업과 촬영지를 넣고, 중간에 종각 다이소도 들러야 해.
> 
> 너무 많이 걷지는 않게 해줘.
> 

챗봇은 임의의 장소를 만들어내는 것이 아니라 서비스의 검증된 장소, 운영시간과 코스 계산 기능을 사용한다.

### 여행 중 대화형 일정 변경

> 지금 너무 힘들어서 카페에서 30분 더 쉬고 싶어.
> 

> 다음 장소는 빼고 실내 장소로 바꿔줘.
> 

현재 위치와 남은 일정을 기준으로 변경 가능한 코스를 제시하고 사용자 승인 후 수정한다.

### 개인화

- 자주 담는 장소 유형
- 실제 체류시간
- 자주 건너뛰는 장소
- 추천·비추천 이유
- 이동 속도
- 공개 코스 저장 기록

을 바탕으로 다음 코스의 장소 수와 체류시간을 조정한다.

### 네이티브 앱 전환

이용 가치가 검증되면 백그라운드 지오펜싱, 안정적인 푸시 알림과 카메라 기능을 위해 앱으로 확장한다.

## 26. 경쟁 서비스와의 차별점

기존 서비스의 개별 기능과 완전히 겹치지 않는 것은 아니다.

- 지도 서비스: 장소 검색·길찾기·리뷰
- 여행 플래너: 장소 저장·코스 생성
- 팝업 플랫폼: 팝업 정보
- 촬영지 앱: 장면과 촬영 위치
- 관광 가이드: 위치 기반 콘텐츠

본 서비스의 차별점은 이 기능을 모두 보유한다는 것이 아니라 다음 세 가지를 하나의 흐름으로 연결한다는 점이다.

### 1. 장소가 아니라 최근 생긴 방문 이유를 발견

### 2. 그 이유가 유효한 시간에 장소를 배치

### 3. 여행 중 상황이 바뀌면 남은 코스를 다시 제안

따라서 경쟁 포지셔닝은 다음과 같이 정의한다.

> **저장한 장소를 단순히 가까운 순서로 연결하는 것이 아니라, 팝업 종료·메뉴 품절·개화·촬영 시간·혼잡처럼 방문 가치가 달라지는 조건을 반영해 서울의 하루 순서를 정해주는 서비스**
>

## 27. 최종 서비스 정의

> **때마은 온라인에서 최근 주목받는 장소와 그 이유를 발견하고, 별도의 장소 검색을 통해 정확한 위치를 연결한다. 사용자는 촬영지, 팝업, 카페, 계절 명소와 개인 필수 일정을 자유롭게 담을 수 있으며, 서비스는 운영시간, 방문 적정 시간, 이동시간과 현장 정보를 고려해 실행 가능한 하루 코스를 만든다. 여행 중에는 현재 위치에 맞는 장면과 주변 정보를 제공하고, 여행 후에는 후기와 코스를 다음 이용자와 공유할 수 있다.**
