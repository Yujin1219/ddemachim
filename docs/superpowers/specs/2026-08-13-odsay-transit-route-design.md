# 홈 장소 선택 ODsay 대중교통 연동 설계

- 상태: 사용자 승인 완료
- 작성일: 2026-08-13
- 적용 범위: `BE/**`, `FE/**`

## 1. 목표

메인 홈 지도에서 장소를 선택하면 현재 위치를 출발지로 사용해 도보·대중교통·택시 예상 시간을 보여준다. 기존 TMAP 경로 비교 기능 중 대중교통만 ODsay로 교체한다. 외부 API 호출량을 아끼기 위해 장소 선택당 ODsay 길찾기 API를 한 번만 호출한다.

## 2. 확정된 사용자 경험

- 장소를 선택하기 전에는 기존 홈 하단 시트를 그대로 보여준다.
- 장소를 선택하면 장소 카드는 유지하고, 그 아래 기존 `코스에 담기`·`카카오맵에서 보기` 행동 행이 `도보 · 대중교통 · 택시` 이동수단 탭으로 교체된다.
- 경로 탭을 기존 행동 행 위에 새 패널로 추가하거나 중복 배치하지 않는다.
- 앱 최하단의 메인 내비게이션은 변경하지 않는다.
- 기본 선택은 도보다. 선택한 탭의 예상 시간과 상세 정보는 같은 교체 영역 안에서 보여준다.
- ODsay 대중교통 결과가 `AVAILABLE`일 때만 대중교통 탭을 표시한다.
- ODsay가 미설정, 시간 초과, 공급자 오류 또는 경로 없음으로 실패하면 대중교통 탭 자체를 숨긴다. 실패 시 대중교통이 선택되어 있었다면 도보, 도보도 불가능하면 택시로 자동 전환한다.
- 대중교통 탭이 숨겨지면 남은 도보·택시 탭을 같은 너비로 배치한다.
- 택시 탭에서는 예상 요금과 `카카오 T로 호출`을 제공한다.

기존 장소 행동은 경로 탭과 동시에 중복 노출하지 않는다. 장소 상세 진입처럼 이미 별도로 존재하는 동작은 유지하되 이번 작업에서 새 행동을 추가하지 않는다.

## 3. 검토한 접근과 선택

### 채택: 공급자 경계 분리

TMAP은 도보와 택시만 담당하고 ODsay는 대중교통만 담당한다. `RouteComparisonService`가 두 공급자를 명시적으로 주입받아 기존 `WALK`, `TRANSIT`, `TAXI` 순서로 결과를 조합한다. 공개 API 응답 계약은 유지한다.

이 방식은 공급자별 키, 타임아웃, 오류 파싱과 테스트를 독립시킨다. TMAP 클래스 안에 ODsay 호출을 섞거나 사용하지 않는 TMAP 대중교통 메서드를 남기는 것보다 책임이 명확하다.

### 제외: 복합 위임 객체

기존 3개 메서드 인터페이스를 구현하는 복합 객체가 내부에서 TMAP과 ODsay로 다시 위임하는 방법은 서비스 변경이 작지만 불필요한 계층과 빈 선택 규칙이 생긴다.

### 제외: 지도 경로선 추가 호출

ODsay 기본 길찾기 응답의 `mapObj`로 `loadLane`을 한 번 더 호출하면 대중교통 선을 그릴 수 있지만, 장소 선택당 호출이 두 번으로 늘어난다. 이번 범위에서는 호출량을 우선해 `loadLane`을 사용하지 않는다.

## 4. 백엔드 구조

```text
RouteController
  -> RouteComparisonService
       -> TmapRouteClient          (WALK, TAXI)
       -> OdsayTransitRouteClient  (TRANSIT)
```

- 공개 엔드포인트 `POST /api/routes/compare`와 `RouteComparisonResponse` 구조는 변경하지 않는다.
- 내부 공급자 포트는 도보·택시와 대중교통 책임을 구분한다.
- `OdsayProperties`는 base URL, 서버 API 키, 연결 및 읽기 타임아웃을 관리한다.
- ODsay 키는 `ODSAY_API_KEY` 환경 변수로만 주입하고 프런트엔드, 응답, 로그에 노출하지 않는다.
- 기존 세 모드 병렬 실행, 부분 성공, 4자리 반올림 좌표 캐시, 최대 2분·1,000건 제한을 유지한다.
- ODsay가 실패해도 TMAP 도보·택시 결과는 폐기하지 않는다.

환경 설정 형태는 다음과 같다.

```yaml
ddemachim:
  odsay:
    base-url: ${ODSAY_BASE_URL:https://api.odsay.com}
    api-key: ${ODSAY_API_KEY:}
    connect-timeout: 2s
    read-timeout: 4s
```

## 5. ODsay 요청과 정규화

한 번의 서버 간 요청으로 `GET /v1/api/searchPubTransPathT`를 호출한다.

- `SX`, `SY`: 현재 위치 경도·위도
- `EX`, `EY`: 선택 장소 경도·위도
- `OPT=0`, `SearchType=0`, `SearchPathType=0`, `lang=0`, `output=json`
- `apiKey`: 서버 설정값

`result.path`의 유효한 후보 중 `info.totalTime`이 가장 작은 한 경로를 선택한다. 동률이면 ODsay 응답에서 먼저 나온 후보를 사용한다.

- `info.totalTime`, `subPath.sectionTime`: 분을 초로 변환
- `info.totalDistance`: 미터 단위 정수로 안전하게 변환
- `info.totalWalk`: 도보 거리
- `info.payment`: 예상 요금
- `info.busTransitCount + info.subwayTransitCount`: 환승 횟수
- `subPath.trafficType` 1·2: `TRANSIT`, 3: `WALK`
- 버스는 `lane.busNo`, 지하철은 `lane.name`을 우선해 `routeName`으로 사용

기본 길찾기 응답에는 완전한 선형 좌표가 없으므로 ODsay가 만든 모든 `RouteLeg.geometry`는 `null`로 둔다. 따라서 대중교통 탭을 선택하면 이전 도보·택시 경로선을 지우고 출발지·목적지 마커만 유지한다. 도보·택시의 TMAP 경로선은 기존대로 표시한다.

## 6. 오류 처리

- 빈 ODsay 키: `NOT_CONFIGURED`
- 검색 결과 없음: `NO_ROUTE`
- 연결·응답 시간 초과: `TIMEOUT`
- 인증, HTTP 오류, 예상하지 못한 응답 구조: `PROVIDER_UNAVAILABLE`

공급자 원문 오류, 요청 URL 전체, API 키는 클라이언트 응답이나 로그에 포함하지 않는다. 프런트엔드는 `TRANSIT`이 `UNAVAILABLE`이면 사유와 관계없이 해당 탭을 렌더링하지 않는다.

ODsay만 실패한 경우 `/api/routes/compare`는 기존 부분 성공 규칙대로 HTTP 200을 반환한다. 모든 공급자가 미설정인 경우에는 기존 `ROUTE5031` 호환 동작을 유지하고, 그 밖의 전체 실패는 `ROUTE5021`을 유지한다.

## 7. 프런트엔드 변경

- `SelectedPlaceRoutePanel`은 계산 중 도보·대중교통·택시 스켈레톤을 표시할 수 있다. 계산 완료 후에는 `TRANSIT`이 `AVAILABLE`일 때만 대중교통 탭을 남긴다. 도보·택시는 기존 오류 표시와 재시도 동작을 유지한다.
- 현재 선택 모드가 제거되면 `WALK`, `TRANSIT`, `TAXI` 우선순위에서 첫 번째 사용 가능한 모드를 선택한다.
- 탭 개수에 따라 CSS 그리드 열을 자동 조정한다.
- `ProductFlow/MapHome`은 선택 장소 카드 다음의 기존 행동 행 대신 경로 탭 블록 하나만 렌더링한다. 현재처럼 경로 패널과 기존 행동 행을 동시에 쌓지 않는다.
- 대중교통 구간의 geometry가 `null`인 것은 정상 상태로 취급하고 지도 오류나 전체 경로 실패로 바꾸지 않는다.
- 현재 위치 조회, 요청 취소, 최신 장소 선택 보호, 카카오 T 연결은 기존 동작을 유지한다.

## 8. 검증

### 백엔드

- ODsay 요청 경로, 좌표, 옵션과 키 전달
- 여러 후보 중 최소 `totalTime` 선택 및 동률 처리
- 분→초, 거리, 요금, 도보 거리, 환승 횟수 변환
- 도보·버스·지하철 구간 순서와 노선명 변환
- 모든 ODsay 구간 geometry가 `null`이고 `loadLane`을 호출하지 않음
- 빈 키, 결과 없음, 시간 초과, HTTP·인증 오류, 잘못된 응답 정규화
- ODsay 실패 시 TMAP 도보·택시가 유지되는 부분 성공
- 응답 순서, 전체 실패 코드와 캐시 동작 유지

### 프런트엔드

- 장소 미선택 시 기존 홈 하단 UI 유지
- 장소 선택 시 기존 행동 행이 경로 탭으로 교체되고 중복 패널이 생기지 않음
- ODsay 성공 시 대중교통 탭 표시
- ODsay의 모든 실패 사유에서 대중교통 탭 제거
- 선택 중인 대중교통이 실패로 바뀔 때 사용 가능한 모드로 자동 전환
- 탭 2개·3개 레이아웃을 320px와 390px에서 확인
- 대중교통 탭 선택 시 낡은 TMAP 경로선 제거
- 전체 프런트엔드 테스트와 프로덕션 빌드, 백엔드 route 테스트와 컴파일

## 9. 완료 기준

- 홈에서 장소를 선택하면 현재 위치 기준 경로 비교가 자동 시작된다.
- ODsay는 선택 좌표쌍당 캐시 미적중 시 한 번만 호출되고 `loadLane`은 호출되지 않는다.
- 대중교통은 정적 예상 소요시간이 가장 짧은 한 경로를 보여준다.
- ODsay 결과가 없거나 실패하면 대중교통 탭 자체가 사라지고 도보·택시 사용에는 영향이 없다.
- 이동수단 탭은 기존 장소 행동 행을 교체하며, 위에 별도 중복 패널로 추가되지 않는다.
- 공개 경로 API 계약과 앱 최하단 메인 내비게이션은 변경되지 않는다.
- 키와 공급자 원문 오류가 저장소, 응답, 로그에 노출되지 않는다.
