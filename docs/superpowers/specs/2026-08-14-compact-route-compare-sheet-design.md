# 홈 경로 비교 시트 축소 설계

- 상태: 사용자 화면 방향 승인 완료
- 작성일: 2026-08-14
- 적용 범위: `FE/**`

## 1. 목표

홈 지도에서 장소를 선택했을 때 도보·대중교통·택시를 빠르게 비교하되, 하단 시트가 지도의 현재 위치와 목적지 마커를 가리지 않게 한다. 기존의 큰 장소 카드와 동일 너비 탭 구조를 없애고, 짧은 비교 행과 선택된 수단의 상세만 노출한다.

핵심 경험은 다음과 같다.

> 장소 선택 → 세 수단의 시간을 한눈에 비교 → 가장 빠른 수단 확인 → 필요한 상세나 호출 행동 실행

## 2. 범위

### 포함

- 선택 장소의 출발지·목적지를 한 줄씩 보여주는 컴팩트 헤더
- 도보·대중교통·택시를 세 개의 비교 행으로 표시
- 이용 가능한 수단 중 소요 시간이 가장 짧은 수단을 최초 자동 선택
- 사용자가 수단을 고른 뒤에는 자동 선택으로 덮어쓰지 않음
- 선택된 수단의 상세만 비교 행 아래에 노출
- 대중교통 공급자 실패 시 대중교통 행 자체를 숨김
- 시트 높이와 내부 여백 축소
- 지도 맞춤 범위에 출발지·목적지를 항상 포함
- 임시 출발지 고정 기간에는 현위치 버튼을 숨기고 `광화문 출발` 문구로 통일

### 제외

- 백엔드 경로 API 또는 공급자 연동 변경
- 사용자가 출발지를 검색하거나 변경하는 기능
- 여러 대중교통 후보를 비교하는 기능
- 카카오 T 호출 방식 변경
- 전체 홈 화면이나 하단 내비게이션 재설계

## 3. 화면 구조

선택 장소 시트는 아래 순서로 구성한다.

1. 드래그 핸들과 닫기 버튼
2. 컴팩트 출발·도착 헤더
3. 이동 수단 비교 행 목록
4. 현재 선택된 수단의 상세와 필요한 주 행동

기존의 큰 `PlaceRow` 카드는 제거한다. 대신 헤더는 다음 정보를 보여준다.

- `출발` — `광화문`
- `도착` — 선택한 장소명
- 내부 장소일 때만 `상세` 보조 버튼
- 시트를 닫는 아이콘 버튼

주소와 출처 로고는 경로 비교의 핵심 판단 정보가 아니므로 시트에서 생략한다. 장소 상세 화면과 외부 지도 이동 기능 자체는 기존 동선에서 유지한다.

## 4. 이동 수단 비교 행

도보, 대중교통, 택시는 각각 최소 44px, 목표 48~52px 높이의 버튼형 행으로 표시한다. 각 행은 왼쪽에 수단명, 오른쪽에 핵심 판단 정보를 둔다.

- 도보: 예상 시간, 거리
- 대중교통: 예상 시간, 환승 횟수
- 택시: 예상 시간, 예상 요금

가장 빠른 이용 가능 수단에는 `가장 빠름` 배지를 붙인다. 최초 경로 응답이 준비되면 이 수단을 자동 선택한다. 사용자가 다른 행을 한 번이라도 누르면 같은 장소가 선택된 동안에는 사용자 선택을 유지한다. 다른 장소를 선택하면 자동 선택 상태를 다시 초기화한다.

선택 행은 배경색, 테두리, 체크 또는 방향 아이콘 중 기존 디자인 토큰에 맞는 최소한의 신호로 구분한다. 시간과 금액은 수단명보다 시각적 우선순위가 높아야 한다. 탭 역할을 흉내 내지 않고 실제 `button` 요소와 `aria-pressed`를 사용한다.

## 5. 상세와 행동

한 번에 선택된 수단 하나의 상세만 보여준다.

- 도보: 총 거리
- 대중교통: 환승 횟수와 도보 거리
- 택시: 예상 요금 안내와 `카카오 T로 호출` 버튼

로딩 중에는 행 안에 짧은 계산 상태를 표시한다. 개별 수단이 일시적으로 이용 불가이면 비활성 상태와 짧은 사유를 표시한다. 단, 대중교통 응답이 `UNAVAILABLE`이면 사용자가 요청한 정책에 따라 대중교통 행을 렌더링하지 않는다. 모든 수단을 조회할 수 없을 때만 기존 전체 오류와 재시도 동작을 유지한다.

## 6. 시트 크기와 지도 가시성

시트는 콘텐츠 높이만 사용하고 최대 높이는 `min(44dvh, 360px)`로 제한한다. 하단 내비게이션 위에 배치해 내비게이션 높이를 시트 내부 패딩으로 중복 확보하지 않는다. 일반 성공 상태에서는 내부 스크롤 없이 전체 비교가 보여야 하며, 작은 화면이나 오류 안내처럼 예외적으로 콘텐츠가 넘칠 때만 시트 내부 스크롤을 허용한다.

지도는 선택 장소가 바뀌었을 때 최초 한 번 다음 좌표를 모두 포함해 맞춘다.

- 임시 출발지인 광화문 좌표
- 선택한 목적지 좌표
- 현재 선택 수단에 경로선 좌표가 있으면 해당 경로선

대중교통처럼 경로선 geometry가 비어 있어도 출발지와 목적지 두 마커는 반드시 보이게 한다. 지도 맞춤의 하단 패딩은 축소된 시트 높이에 맞춰 약 330px 수준으로 줄인다. 사용자가 지도를 직접 움직인 뒤에는 단순 수단 전환만으로 지도를 다시 강제 이동하지 않는다.

임시 출발지 고정 중에는 실제 기기 위치를 뜻하는 현위치 버튼을 숨긴다. UI 문구는 `현재 위치` 대신 `광화문 출발`로 통일해 표시와 실제 요청 좌표가 다르게 보이지 않게 한다.

## 7. 상태와 데이터 흐름

`MapHome`이 선택 장소, 경로 응답, 사용자가 수동으로 고른 수단을 관리한다. `SelectedPlaceRoutePanel`은 정규화된 수단 목록과 선택 상태를 받아 비교 행과 상세를 렌더링한다. 가장 빠른 수단 계산은 이용 가능하고 유효한 `durationSeconds`가 있는 응답만 대상으로 하는 순수 함수로 분리한다.

`VWorldMap`에는 경로선과 별도로 출발·도착 좌표를 전달한다. 지도 맞춤 로직은 경로선 extent와 두 끝점 extent를 합쳐 사용하며, 장소별 fit key를 통해 같은 장소에서 반복 맞춤이 일어나지 않게 한다.

## 8. 접근성과 반응형

- 모든 비교 행과 `상세`, 닫기, 호출 행동은 키보드로 접근 가능해야 한다.
- 선택 상태는 색만으로 구분하지 않고 `aria-pressed`와 시각적 표식을 함께 제공한다.
- 계산 및 오류 상태는 기존 live region을 유지한다.
- 320px 너비에서도 수단명, 시간, 보조 정보가 겹치지 않아야 한다.
- 터치 대상은 최소 44px를 유지한다.
- 긴 목적지명은 한 줄 말줄임하고 전체 이름을 접근 가능한 이름으로 보존한다.

## 9. 검증 전략

### 자동 검증

- 이용 가능한 수단 중 최단 시간 수단 선택
- 대중교통 `UNAVAILABLE` 시 행 숨김과 선택 fallback
- 사용자의 수동 선택 유지 및 장소 변경 시 초기화
- 비교 행의 핵심 정보와 선택 접근성 속성
- 출발·도착 좌표가 지도 맞춤 입력에 포함됨
- 기존 택시 호출, 상세 이동, 닫기 동작 회귀 방지
- 프런트엔드 테스트와 프로덕션 빌드

### 수동 검증

- 320px, 390px 모바일 뷰포트에서 시트 높이와 겹침
- 광화문과 목적지 마커가 시트 위 지도 영역에 함께 노출되는지 확인
- 대중교통 geometry가 없는 응답에서도 두 마커 노출 확인
- 도보·대중교통·택시 행 전환과 택시 호출 버튼 확인
- 로딩, 부분 실패, 전체 실패 상태에서 시트가 과도하게 커지지 않는지 확인

## 10. 완료 기준

- 장소 선택 직후 큰 장소 카드 대신 컴팩트 출발·도착 헤더가 보인다.
- 모든 이용 가능 수단의 시간과 핵심 보조 정보를 펼치지 않고 비교할 수 있다.
- 가장 빠른 수단이 최초 선택되고, 이후 사용자의 선택은 유지된다.
- 대중교통 실패 시 대중교통 행이 사라지고 다른 수단은 정상 동작한다.
- 정상 성공 상태의 시트가 360px을 넘지 않고 하단 내비게이션과 중복되지 않는다.
- 출발지와 목적지 마커가 시트에 가리지 않도록 지도 범위가 맞춰진다.
- 임시 광화문 출발 상태에서 현위치 버튼과 `현재 위치` 오해 요소가 노출되지 않는다.
- 관련 테스트와 프런트엔드 빌드가 통과한다.
