# Course Save and Start Design

## Goal

사용자가 코스 미리보기에서 하나의 코스를 확정하면 서버에 저장한다. 예약한 코스는 코스 탭의 예정 목록에 표시하고, 예정 코스를 선택하면 저장된 단일 코스만 미리보기로 다시 보여준다. `지금 바로`를 선택한 코스나 예정 코스의 `시작하기`를 누른 경우 실제 진행 중 상태로 전환한다.

## Scope

- 코스 생성 첫 화면에 `지금 바로`와 `일정 예약` 선택을 추가한다.
- 미리보기의 선택 전략과 사용자가 고른 구간별 경로를 하나의 확정 코스로 저장한다.
- 예정 코스 목록과 저장된 단일 코스 상세를 서버 데이터로 제공한다.
- 저장과 동시에 시작하거나, 예정 코스를 나중에 시작할 수 있다.
- 이미 진행 중인 코스가 있으면 사용자 확인 후 기존 코스를 `ARCHIVED`로 종료하고 새 코스를 시작한다.
- 진행 화면의 코스 제목, 장소 순서, 예정 시각을 저장된 코스 데이터와 연결한다.

이번 범위에는 GPS 방문 판정, 장소별 완료 기록, 일시정지, 재계산 이력 생성, 완료 코스 목록의 서버 연동을 포함하지 않는다.

## Domain Model

기존 `Course`, `CourseRevision`, `CourseStop` 집합을 사용한다.

- `Course.status`
  - `READY`: 예정 코스
  - `IN_PROGRESS`: 현재 진행 중인 코스
  - `ARCHIVED`: 다른 코스를 시작하기 위해 중간 종료한 코스
  - `COMPLETED`: 기존 완료 상태이며 이번 범위에서는 전환하지 않는다.
- `Course.currentRevision`은 사용자가 확정한 선택 코스를 가리킨다.
- `CourseRevision`은 날짜, 출발 희망 시각, 출발점, 전략을 보존한다.
- `CourseStop`은 장소 순서, 장소 스냅샷, 체류시간, 예정 도착·출발 시각과 이동 지표를 보존한다.
- `course_stop.selected_route_snapshot jsonb`를 추가해 사용자가 확정한 구간 경로를 그대로 다시 표시한다. 대안 경로는 저장하지 않는다.

코스 제목은 별도 입력을 받지 않고 첫 장소를 기준으로 서버에서 생성한다. 장소가 여러 개면 `경복궁 외 3곳`, 하나면 `경복궁` 형식을 사용한다.

## Course Creation

코스 생성 첫 화면은 `startTiming` 값을 관리한다.

- `NOW`: 미리보기 생성 시 서울 기준 오늘 날짜와 현재 시각을 사용하고, 최종 저장 요청에서는 서버의 현재 날짜와 시각으로 다시 계산한다. 날짜와 출발 시각을 별도로 편집하지 않는다.
- `SCHEDULED`: 사용자가 기존 날짜와 출발 시각 입력을 사용한다.

미리보기에서는 기존 전략 탭과 구간별 경로 선택을 유지한다. 사용자가 저장 버튼을 누르면 원본 미리보기 요청, 선택 전략, 구간별 선택 이동수단, 시작 방식과 충돌 교체 여부를 서버에 전달한다. 서버는 장바구니 소유권과 입력을 다시 검증하고 코스를 다시 계산한 뒤, 해당 전략과 구간 선택을 적용한 한 개의 확정 결과만 저장한다.

`NOW` 생성은 저장과 시작을 하나의 트랜잭션으로 처리한다. 진행 중 코스가 있고 `replaceActive=false`이면 아무 코스도 생성하지 않고 충돌을 반환한다. 사용자가 종료 후 시작을 확인해 `replaceActive=true`로 다시 요청하면 기존 진행 코스를 `ARCHIVED`로 바꾸고 새 코스를 `IN_PROGRESS`로 저장한다.

`SCHEDULED` 생성은 코스를 `READY`로 저장하고 코스 탭의 예정 목록으로 이동한다.

## API Contract

### Create course

`POST /api/courses`

요청은 다음 의미의 값을 포함한다.

- `previewRequest`: 기존 `CoursePreviewRequest`
- `strategy`: `FAST`, `EASY`, `QUIET` 중 사용자가 선택한 전략
- `routeSelections`: 장바구니 항목별 사용자가 선택한 이동수단
- `startTiming`: `NOW` 또는 `SCHEDULED`
- `replaceActive`: 진행 중 코스를 종료하고 시작할지 여부

응답은 생성된 코스 ID, 상태, 제목과 저장된 단일 코스 상세를 반환한다. 성공 상태는 `201 Created`다.

### List courses

`GET /api/courses?status=READY`

본인의 예정 코스를 여행 날짜와 출발 시각 오름차순으로 반환한다. 코스 탭은 이 응답을 예정 목록으로 사용한다.

진행 중 카드 조회에는 `GET /api/courses?status=IN_PROGRESS`를 사용하며 서버는 한 사용자에게 최대 한 개의 진행 중 코스만 허용한다.

### Get course detail

`GET /api/courses/{courseId}`

본인 소유 코스의 현재 리비전과 저장된 경로 스냅샷을 단일 코스 상세로 반환한다. 프론트엔드는 기존 미리보기 컴포넌트를 읽기 전용 모드로 사용하고 전략 탭이나 조건 수정 버튼을 표시하지 않는다.

### Start scheduled course

`POST /api/courses/{courseId}/start`

요청은 `replaceActive`를 포함한다. 대상 코스는 본인 소유 `READY` 상태여야 한다. 진행 중 코스가 없으면 대상을 `IN_PROGRESS`로 바꾼다. 진행 중 코스가 있고 `replaceActive=false`이면 충돌을 반환하며, `true`이면 기존 코스를 `ARCHIVED`로 바꾸고 대상을 시작한다. 이 전환 전체는 하나의 트랜잭션에서 수행한다.

## Frontend Flow

### New course

1. 사용자가 출발 위치와 `지금 바로` 또는 `일정 예약`을 선택한다.
2. 장소별 시간을 설정하고 미리보기를 생성한다.
3. 전략과 필요한 구간별 경로를 선택한다.
4. `NOW`이면 `이 코스로 지금 시작`, `SCHEDULED`이면 `예정 코스로 저장` 버튼을 표시한다.
5. 저장 성공 시 `NOW`는 진행 화면, `SCHEDULED`는 코스 탭 예정 목록으로 이동한다.

### Scheduled course

1. 코스 탭은 `READY` 목록을 서버에서 조회한다.
2. 예정 항목을 누르면 해당 코스 상세를 조회한다.
3. 저장된 옵션 하나만 기존 미리보기 UI로 표시한다.
4. 하단에는 `시작하기` 버튼만 제공한다.
5. 시작 성공 시 진행 화면으로 이동한다.

### Active course conflict

새 코스를 시작하려는데 진행 중 코스가 있으면 기존 코스를 종료할지 확인한다. 취소하면 현재 화면과 기존 진행 코스를 유지한다. 확인하면 같은 요청을 `replaceActive=true`로 다시 보내고 성공 후 새 진행 화면으로 이동한다.

### Active course display

코스 탭 상단에는 진행 중 코스가 있을 때 별도 카드를 표시한다. 기존 `active-course` 화면은 저장된 코스 제목, 장소 순서와 예정 시각을 사용한다. GPS 방문 판정과 진행률 저장은 목업 상태를 확장하지 않는다.

## Minimal Error Handling

- 인증 만료는 기존 로그인 복귀 흐름을 사용한다.
- 진행 중 코스 충돌은 종료 후 시작 확인 UI로 처리한다.
- 저장, 목록, 상세, 시작 실패는 공통 오류 문구와 재시도만 제공한다.
- 요청 중에는 관련 버튼을 비활성화해 중복 요청을 막는다.
- 존재하지 않거나 다른 사용자 소유인 코스는 동일한 `404`로 응답한다.
- 허용되지 않는 상태 전환은 `409`로 응답한다.

## Minimal Verification

백엔드는 다음 핵심 동작만 자동 검증한다.

- 예정 코스 저장
- 즉시 시작 저장
- 기존 진행 코스를 `ARCHIVED`로 바꾸고 새 코스 시작
- 소유권 검증

프론트엔드는 다음 핵심 흐름만 자동 검증한다.

- 예정 저장 후 코스 탭 이동
- 예정 코스 선택 시 저장된 단일 옵션 표시
- 즉시 시작과 예정 코스 시작 요청

마지막으로 백엔드 테스트와 컴파일, 프론트엔드 테스트와 프로덕션 빌드를 실행한다.

## Data and Migration Safety

마이그레이션은 `course_stop.selected_route_snapshot jsonb`를 nullable로 추가해 기존 행과 호환한다. 기존 코스·리비전·장소 데이터를 삭제하거나 재작성하지 않는다. 코스 생성과 상태 교체는 트랜잭션으로 처리하며, 다른 사용자의 장바구니 항목과 코스를 참조할 수 없다.
