# 장소 선택 후 경로 비교 설계

- 상태: 사용자 화면 방향 승인 완료
- 작성일: 2026-08-13
- 적용 범위: `FE/**`, `BE/**`

## 1. 목표

메인 지도에서 검색 결과나 지도 마커로 장소를 선택하면, 출발지를 현재 위치로 고정해 도보·대중교통·택시의 예상 소요 시간을 한 번에 보여준다. 사용자는 대중교통은 가장 빠른 한 경로만 확인하고, 택시는 카카오 T 앱으로 이동해 호출을 마무리할 수 있어야 한다.

핵심 경험은 다음 한 문장으로 정의한다.

> 장소 선택 → 현재 위치 확인 → 세 이동 수단 비교 → 선택한 경로 확인 → 필요하면 카카오 T로 이동

## 2. 범위와 비범위

### 포함

- 카카오 장소 검색 결과와 서비스 내부 장소 마커 모두에서 동일한 경로 비교 패널 제공
- 출발지의 초기값과 MVP 동작을 현재 위치로 고정
- 도보, 대중교통, 택시 예상 시간·거리 제공
- 대중교통은 총소요 시간이 가장 짧은 한 경로만 노출
- 택시는 예상 요금과 카카오 T 호출 버튼 제공
- 선택한 이동 수단의 경로선을 지도에 표시
- 위치 거부, 일부 경로 실패, 경로 없음, 외부 앱 이동 실패를 독립적으로 처리

### 제외

- 사용자가 출발지를 직접 검색하거나 변경하는 기능
- 여러 대중교통 후보 비교 및 사용자가 정렬 기준을 바꾸는 기능
- 카카오 T 내부의 실제 배차·결제·호출 완료 처리
- 길안내 내비게이션, 실시간 이동 추적, 백그라운드 위치 수집
- 경유지와 왕복 경로

## 3. 화면 구조와 상호작용

장소 선택 시 기존 하단 시트 안에서 아래 순서로 확장한다.

1. 기존 장소 카드: 출처, 장소명, 주소를 그대로 유지한다.
2. `현재 위치에서` 제목과 위치 상태를 표시한다.
3. 도보·대중교통·택시 3개 모드 탭에 각 예상 시간을 노출한다.
4. 선택한 탭의 상세 정보와 경로 요약을 펼친다.
5. 택시 탭일 때만 `카카오 T로 호출` 노란색 주 행동 버튼을 노출한다.
6. 기존 `코스에 담기`, `카카오맵에서 보기`는 하단의 보조 행동으로 유지한다.

기본 선택 탭은 도보다. 사용자가 탭을 바꾸면 상세 정보와 지도 경로선이 함께 바뀐다. 각 탭은 실제 `button` 요소와 `aria-pressed`를 사용하며, 계산 상태와 오류 문구는 스크린리더가 인지할 수 있도록 live region으로 제공한다.

### 장소 선택 규칙

- 카카오 검색 결과 선택: 현재처럼 장소 카드를 보여주고 경로 계산을 시작한다.
- 외부 카카오 마커 선택: 선택된 장소 패널을 펼치고 경로 계산을 시작한다.
- 내부 장소 마커 선택: 바로 상세 페이지로 이동하지 않고 먼저 동일한 선택 패널을 연다. 장소 카드 또는 별도 `장소 상세` 동작을 통해 기존 상세 페이지로 갈 수 있게 한다.
- 다른 장소를 선택하면 이전 요청을 취소하고 경로선과 결과를 즉시 초기화한다.

### 주요 상태

| 상태 | 패널 표현 | 가능한 동작 |
| --- | --- | --- |
| 위치 확인 중 | `현재 위치 확인 중…`과 탭 스켈레톤 | 장소 보조 행동 |
| 경로 계산 중 | 위치는 확정, 각 탭은 계산 중 | 탭 선택, 장소 보조 행동 |
| 완료 | 시간·거리·상세·경로선 | 탭 전환, 카카오 T 이동 |
| 일부 실패 | 성공한 모드는 사용 가능, 실패 모드는 사유 표시 | 성공한 탭 전환, 실패 모드 재시도 |
| 위치 거부/실패 | 권한 안내와 `다시 시도` | 장소 보조 행동 |
| 전체 실패 | 패널 내 재시도 오류 | 장소 보조 행동 |

하단 시트는 작은 화면에서도 지도 전체를 가리지 않도록 콘텐츠 영역만 스크롤하고, 주 행동 버튼은 손가락으로 누르기 쉬운 최소 44px 높이를 유지한다. 320px와 390px 너비에서 모드 이름·시간이 줄바꿈 없이 읽혀야 한다.

## 4. 위치 처리

- 목적지가 선택된 시점에 브라우저 Geolocation API로 현재 위치를 한 번 요청한다.
- 기존 현위치 버튼과 경로 비교가 같은 위치 상태를 공유해 중복 권한 요청을 만들지 않는다.
- 권장 옵션은 `enableHighAccuracy: true`, `timeout: 10000`, `maximumAge: 30000`이다.
- 위치는 프런트엔드 메모리에서만 유지하고 로컬 스토리지, 세션 스토리지, 서버 로그에 저장하지 않는다.
- MVP에서는 위치를 계속 추적하지 않는다. 이동 후 최신 예상 시간이 필요하면 사용자가 재시도/새로고침한다.
- 권한 거부 시 경로 API를 호출하지 않고, 브라우저 설정 안내와 `다시 시도`를 제공한다.

## 5. 프런트엔드 구조

### 책임 분리

- `ProductFlow/MapHome`: 선택 장소와 하단 시트의 상위 상태를 관리한다.
- `useCurrentLocation`: 현위치 조회, 재사용, 오류 정규화를 담당한다.
- `useRouteComparison`: 요청 취소, 로딩/부분 성공/재시도 상태를 관리한다.
- `SelectedPlaceRoutePanel`: 장소 카드, 모드 탭, 상세, 행동 버튼을 렌더링한다.
- `VWorldMap`: 선택 모드의 정규화된 경로 구간을 벡터 레이어로 그린다.
- `api/client`: 경로 비교 API 호출과 DTO 타입/정규화를 담당한다.

프로젝트가 현재 JSX 기반이므로 이번 작업에서 TypeScript 전환은 하지 않는다. 새 UI는 기존 토큰, 아이콘, 버튼 패턴을 재사용한다.

### 경로선

- 도보, 대중교통, 택시 각각 구분되는 색과 선 스타일을 사용한다.
- 대중교통은 환승 구간별 `mode`와 `routeName`을 보존해 버스/지하철/도보 구간을 구분할 수 있게 한다.
- 경로 결과를 처음 받은 경우에만 출발지와 목적지가 함께 보이도록 지도를 맞춘다. 사용자가 이후 지도를 직접 움직이면 탭 전환만으로 시점을 강제로 되돌리지 않는다.
- 장소 변경, 패널 닫기, 요청 실패 시 이전 경로 레이어를 제거한다.

## 6. 백엔드 API 계약

### 요청

`POST /api/routes/compare`

```json
{
  "origin": {
    "latitude": 37.5665,
    "longitude": 126.9780
  },
  "destination": {
    "latitude": 37.5559,
    "longitude": 126.9723
  }
}
```

- 위도는 `-90..90`, 경도는 `-180..180` 범위의 유한한 숫자여야 한다.
- 출발지와 목적지는 필수다.
- 장소명·사용자 식별자처럼 경로 계산에 필요하지 않은 값은 서버로 보내지 않는다.

### 응답

기존 공통 응답 래퍼의 `result` 안에 다음 구조를 반환한다. `routes` 순서는 `WALK`, `TRANSIT`, `TAXI`로 고정한다.

```json
{
  "isSuccess": true,
  "code": "ROUTE2001",
  "message": "경로 비교 조회에 성공했습니다.",
  "result": {
    "generatedAt": "2026-08-13T12:00:00Z",
    "routes": [
      {
        "mode": "WALK",
        "status": "AVAILABLE",
        "durationSeconds": 840,
        "distanceMeters": 920,
        "fareWon": null,
        "transferCount": null,
        "walkDistanceMeters": 920,
        "unavailableReason": null,
        "legs": [
          {
            "mode": "WALK",
            "routeName": null,
            "durationSeconds": 840,
            "distanceMeters": 920,
            "geometry": {
              "type": "LineString",
              "coordinates": [[126.9780, 37.5665], [126.9723, 37.5559]]
            },
            "steps": []
          }
        ]
      }
    ]
  }
}
```

### 응답 규칙

- `status`: `AVAILABLE` 또는 `UNAVAILABLE`
- `unavailableReason`: `NO_ROUTE`, `PROVIDER_UNAVAILABLE`, `NOT_CONFIGURED`, `TIMEOUT` 중 하나
- `fareWon`: 대중교통 요금 또는 TMAP 자동차 경로의 택시 예상 요금. 제공되지 않으면 `null`
- `transferCount`, `walkDistanceMeters`: 대중교통에서만 의미가 있으며 다른 모드는 `null` 가능
- `legs`: 공급자 응답을 서비스 공통 형식으로 정규화한 구간 목록
- `legs[].steps`: 대중교통 경로의 `WALK` 구간은 TMAP이 반환한 도보 단계를 순서대로 담고, 그 외 구간은 빈 배열을 반환한다. 각 단계는 도로명, 거리, 안내 문구, GeoJSON 선형 좌표를 포함할 수 있다.
- 경로 좌표는 GeoJSON 순서인 `[longitude, latitude]`를 사용한다.
- 한 모드만 성공해도 HTTP 200과 전체 세 모드 상태를 반환한다.
- 모든 모드가 실패하면 공통 오류 응답과 HTTP 502를 반환한다.
- 잘못된 좌표는 HTTP 400, TMAP 설정이 전체적으로 빠진 경우는 HTTP 503을 반환한다.

## 7. TMAP 연동

백엔드에 `domain.route` 경계를 만들고 다음 흐름으로 구성한다.

```text
RouteController
  → RouteComparisonService
    → TmapRouteClient
      ├─ 도보 경로
      ├─ 대중교통 경로
      └─ 자동차 경로(택시 표시용)
```

- 도보: `POST /tmap/routes/pedestrian?version=1`
- 대중교통: `POST /transit/routes`, `count=10` 요청. 응답이 여러 개면 `totalTime` 최솟값을 최종 경로로 선택하고, 선택한 경로의 `WALK` 구간 도보 단계를 공통 응답으로 정규화한다.
- 택시: `POST /tmap/routes?version=1`, 교통정보 기반 기본 최적 경로의 `totalTime`, `totalDistance`, `taxiFare`를 사용한다.
- 세 외부 요청은 전용 제한된 실행기에서 병렬 수행한다. 한 요청의 예외가 다른 모드 결과를 폐기하지 않도록 각각 오류 상태로 변환한다.
- 연결/응답 시간 제한을 두고, 공급자 원문 오류나 키를 클라이언트와 로그에 노출하지 않는다.
- 동일한 근거리 요청은 위·경도를 소수점 넷째 자리로 반올림한 키로 메모리에서 최대 2분 캐시한다. 최대 엔트리 수를 제한하고 디스크에 저장하지 않는다.
- TMAP 이용 조건상 API 데이터는 장기 저장하지 않으며 모든 캐시는 24시간보다 훨씬 짧게 유지한다.

환경 설정 예시는 다음과 같다. 앱 키는 저장소에 커밋하지 않는다.

```yaml
ddemachim:
  tmap:
    base-url: https://apis.openapi.sk.com
    app-key: ${TMAP_APP_KEY:}
    connect-timeout: 2s
    read-timeout: 4s
    cache-ttl: 2m
```

배포 전에 TMAP 프로젝트에서 도보·자동차·대중교통 API 상품 사용 권한과 일일 쿼터를 확인해야 한다. 특히 대중교통 경로 API는 계약 상품에 따라 무료 호출량이 매우 작을 수 있으므로 운영 모니터링 대상이다.

## 8. 카카오 T 이동

`카카오 T로 호출`은 서비스가 택시를 직접 배차하는 버튼이 아니다. 사용자의 현재 위치를 출발지로 삼고 선택 장소 좌표를 목적지로 전달해 카카오 T를 여는 외부 앱 핸드오프다. 실제 목적지 확인, 호출, 결제는 카카오 T 안에서 끝난다.

카카오가 공개 개발자 API로 택시 호출 계약을 제공하지 않으므로 다음 안전장치를 둔다.

- 모바일에서는 설정 가능한 카카오 T 실행 URL 템플릿에 목적지 위·경도를 넣어 best-effort로 연다.
- 템플릿 기본값은 카카오 T의 웹 실행 주소를 사용하되, 파라미터 동작은 보장하지 않는다는 점을 코드 주석과 운영 문서에 명시한다.
- 데스크톱이거나 앱 실행을 보장할 수 없는 경우 카카오 T 서비스 안내 페이지를 새 탭으로 연다.
- 버튼 근처에 `앱에서 출발지와 목적지를 확인한 뒤 호출을 완료해주세요.`라는 안내를 제공한다.
- 팝업 차단 또는 URL 생성 실패 시 패널 안에 재시도 가능한 오류를 보여준다.

## 9. 오류·경계 조건

- 목적지가 현위치와 사실상 동일하면 외부 API를 호출하지 않고 `이미 목적지 근처예요`를 표시한다.
- 빠르게 여러 장소를 선택할 때 이전 `AbortController` 요청의 결과가 최신 선택을 덮어쓰지 않게 한다.
- 대중교통 경로가 없더라도 도보·택시 결과를 유지한다.
- 택시 예상 요금은 실제 교통·할증·호출료와 다를 수 있으므로 `예상` 표현을 붙인다.
- 좌표가 없거나 유효하지 않은 내부 장소는 경로 탭 대신 `이 장소는 경로를 계산할 수 없어요`를 표시한다.
- 시트가 닫혀도 외부 앱 이동 후 돌아왔을 때 사용자가 선택 장소를 다시 찾을 수 있도록 선택 상태는 현재 페이지 메모리에서 유지한다.
- API 요청/응답 로그에는 정밀 위치와 TMAP 앱 키를 기록하지 않는다.

## 10. 검증 전략

### 백엔드 자동 검증

- 요청 좌표 유효성 및 공통 응답 형식 컨트롤러 테스트
- TMAP 도보·대중교통·자동차 각각의 URL, 헤더, 요청 본문, 응답 매핑 테스트
- 대중교통 복수 후보 중 최소 `totalTime` 선택 테스트
- 한 모드 실패 시 부분 성공, 전체 실패 시 502 테스트
- 동일 반올림 좌표의 캐시 적중과 TTL 만료 테스트
- 공급자 오류 본문과 앱 키가 응답에 포함되지 않는지 테스트

### 프런트엔드 검증

- `npm run build`
- 위치 허용/거부/시간 초과/재시도 수동 시나리오
- 검색 장소, 외부 마커, 내부 마커의 동일 패널 동작
- 세 탭의 로딩·성공·부분 실패·경로선 교체
- 카카오 T 버튼의 모바일/데스크톱 폴백
- 320px, 390px, 데스크톱 너비와 키보드 탐색
- 브라우저 콘솔 오류와 네트워크 중복 요청 확인

## 11. 완료 기준

- 장소 선택 후 사용자의 추가 입력 없이 현재 위치 기준 계산이 시작된다.
- 성공한 각 모드에 예상 시간과 거리가 보이고, 대중교통은 가장 빠른 한 경로만 보인다.
- 택시 탭에서 예상 요금과 카카오 T 호출 버튼이 보인다.
- 선택 모드의 경로선이 지도에 표시되고 장소 변경 시 낡은 결과가 남지 않는다.
- 위치 거부나 일부 공급자 실패가 기존 장소 보기·코스 담기 기능을 막지 않는다.
- TMAP 키와 정밀 위치가 저장소, 응답 오류, 애플리케이션 로그에 노출되지 않는다.
- 백엔드 관련 테스트와 프런트엔드 프로덕션 빌드가 통과한다.

## 12. 알려진 위험과 후속 결정

- 카카오 T 목적지 전달 URL은 공개적으로 보장된 호출 API가 아니므로 앱 버전에 따라 목적지가 자동 입력되지 않을 수 있다. 운영 전 실제 iOS/Android 기기 검증이 필요하다.
- 대중교통 API 쿼터와 비용은 TMAP 계약 상품에 의존한다. 트래픽이 커지면 짧은 캐시 외에 사용자별 호출 제한과 사용량 알림을 추가해야 한다.
- 외부 공급자의 ETA와 실제 도착 시간은 다를 수 있으므로 UI에서 모두 예상값으로 표현한다.
